# 5-3 按键计时器 —— 使用说明

一个用 **2 个按键 + OLED** 做的计时器，两种模式：**秒表** 和 **倒计时**。

> **前置知识：TIM 定时中断（江协 6-1）**
>
> 这个工程的核心是 `Timer.c` 里的 TIM2 定时中断，内容就是 6-1 那一节。

## 一、做出来长什么样

**秒表模式**

```
STOPWATCH
   00:12.34      ← 分:秒.百分秒
> RUN           ← > RUN / > PAUSE
K1:GO K2:CLR    ← 按键提示
```

**倒计时模式**

```
COUNTDOWN
   00:00.42      ← 剩余时间
> TIME UP!      ← 到点时会闪，蜂鸣器断续叫
SET 01:00 K2:SET ← 当前设定的时长
```

## 二、按键怎么用

| 操作 | 秒表模式 | 倒计时模式 |
|---|---|---|
| **KEY1 短按** | 开始 / 暂停 / 继续 | 开始 / 暂停；响完后按 = 重新计时 |
| **KEY2 短按** | 清零并停表 | 停着时按 = 换时长档位（30s→1min→2min→5min→10min 循环）<br>跑着时按 = 中止并归零（时长不变） |
| **KEY2 长按 1 秒** | 切换到倒计时 | 切换到秒表 |

长按判定是"按住满 1000ms 立刻生效"，不用等松手。

| 模块 | 引脚 | 说明 |

## 五、为什么这次不能再抄 3-4 的 `Key_GetNum()`

你 3-4 写的那版是这样的：

```c
if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1) == 0)
{
    Delay_ms(20);
    while (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1) == 0);   // ← 死等松手
    Delay_ms(20);
    KeyNum = 1;
}
```

点灯的程序这么写没问题，因为按住键的时候"什么都不用做"。

但计时器不行。你按住键不放的那一秒里：

- 主循环卡在 `while` 里出不来
- OLED 不刷新，屏幕上的数字冻住
- 蜂鸣器不响
- 计时也停

**所以按键必须"扫一眼就走"，不能等。** 这就是 Key.c 改写成非阻塞的原因：

- 每次进来只读一下电平，立刻返回
- 靠"电平是**什么时候**变的"来判断，而不是靠在原地等
- 稳定 20ms 才算数（消抖）、按住 1000ms 算长按、松手时算短按

这个套路（读电平 → 记时刻 → 时间差判断）是嵌入式里所有"非阻塞"逻辑的通用写法，
以后写菜单、连按、双击，都是它。

## 六、TIM 定时中断是怎么配出来的

这是这个工程唯一的新知识，也是你今晚要学的部分。

### 1. 为什么需要它

STM32 里能计时的东西不少，但都不合适：

| 方案 | 问题 |
|---|---|
| `Delay_ms(10)` 后再累加 | 刷一次 OLED 要好几十毫秒，这段时间被漏掉，一分钟能慢好几秒 |
| `ElapsedMs++` 靠循环次数 | 每轮循环耗时不一样，跑得忽快忽慢 |
| SysTick（Delay.c 用的那个） | 已经被 `Delay_us()` 占用了，而且它是"用完就关"，不适合连续计时 |
| **TIM2 定时中断** | 硬件自己数数，到点就打断 CPU 一下，主循环干什么都不影响它 ✅ |

### 2. 一秒钟是怎么被切成 1 毫秒的

TIM2 挂在 APB1 总线上，时钟 **72MHz**，也就是 1 秒能数 72000000 个数。太多，得先降速：

```
72MHz ──[PSC 预分频 = 72]──→ 1MHz ──[ARR 数到 1000]──→ 每 1ms 溢出一次
         每数一个数 = 1us                溢出就产生"更新中断"
```

两个寄存器：

| 寄存器 | 你填的值 | 实际含义 |
|---|---|---|
| `TIM_Prescaler` (PSC) | **72 - 1 = 71** | 72 分频，72MHz → 1MHz |
| `TIM_Period` (ARR) | **1000 - 1 = 999** | 数 1000 个数溢出一次 |

**为什么要减 1**：硬件是从 **0** 开始数的。想数 1000 个数，是数 0,1,2,...,999，
所以装进去的是 999。PSC 同理，72 分频装 71。

填 `1000 / 72` 而不是 `999 / 71`，也能跑，但中断周期变成 1001us，
走时会比真实时间慢 0.1% —— 一小时慢 3.6 秒。这种误差在秒表上看不出来，
但如果你以后做"计时 24 小时"的项目，这就是 86 秒。

### 3. 中断是怎么被放行的

一条链路，任何一环断了都进不去中断：

```
计数溢出
  → TIM_ITConfig(TIM2, TIM_IT_Update, ENABLE)    开了"更新中断"这个开关
  → NVIC_Init(NVIC_IRQChannel = TIM2_IRQn)        NVIC 允许这个通道打断 CPU
  → TIM_Cmd(TIM2, ENABLE)                         定时器本身得先跑起来
  → TIM2_IRQHandler()                             启动文件里登记好的函数名
```

四个环节对应骨架里第 2、3 步要填的东西。

**`TIM_ClearFlag(TIM2, TIM_FLAG_Update)` 那句别漏**：初始化的时候计数器可能已经
溢出过一次，标志位挂着。你 `TIM_ITConfig` 一开，它立刻就冲进去执行一次中断。
清一下，从干净状态开始。

### 4. 中断里为什么只写一句 `Timer_Tick++`

中断服务函数的原则：**能多短就多短**。

因为中断执行的时候，主循环是完全停住的。你在中断里刷一次 OLED（几十毫秒），
主循环就会被冻住几十毫秒，而且每 1ms 就要冻一次 —— 程序直接废掉。

所以中断里只做最必要的一件事：**记下"又过了 1 毫秒"**。
真正的活（刷屏、判断、响蜂鸣器）全留给主循环。

这也是为什么 `Timer_Tick` 前面必须加 `volatile`：
它在中断里被改、在主循环里被读，不加的话编译器会以为"主循环里没人改它"，
把它缓存到寄存器里，于是主循环永远读到 0 —— 秒表一动不动。
这种 bug 编译器不报错，只能靠你记得加。

### 5. 主循环怎么用这个心跳

```c
Now = Timer_GetTick();          // 现在几点了（毫秒）
ElapsedMs += Now - LastTick;    // 从上一轮到现在过了多久，加进去
LastTick = Now;                 // 把"上一轮"更新成现在
```

这就是**时间戳差分法**。它有个特别好的性质：**你刷屏刷了 50ms 还是 5ms 都无所谓**，
因为加进去的是"真实流逝的时间"，不是"你以为流逝的时间"。

对比一下错误写法：

```c
ElapsedMs += 10;
Delay_ms(10);        // ← 实际每轮花了 10ms + 刷屏 40ms = 50ms
                     //   但只加了 10，越跑越慢
```

## 八、四个必踩的坑

### 1. PSC 和 ARR 都要减 1

72MHz 想要 1ms，填的是 `72-1` 和 `1000-1`。填 `72` 和 `1000` 也能跑，
但周期是 1001us。见上面第六节第 2 点。

### 2. 中断函数名一个字母都不能改

必须是 `TIM2_IRQHandler`。写成 `TIM2_IRQhandler`（小写 h）、
`TIM2_Handler`、`TIM2_IRQHandler_`，编译全都不报错，
但**中断永远进不去**，你面对的是一块不动的屏幕。

名字是 `startup_stm32f10x_md.s` 里登记死的，和你 5-1、5-2 写 `EXTI0_IRQHandler`
是同一个道理。

### 3. `volatile` 不能省

`static volatile uint32_t Timer_Tick = 0;`

中断里改、主循环读的变量，全都要加。不加的话编译器优化之后，
主循环可能一直在读一个早已过期的值。

判断标准很简单：**这个变量是不是在中断里被改过？** 是 → 加 `volatile`。

### 4. 这个工程里一次 `Delay_ms()` 都不能用

不是"少用"，是"不能用"。

`Delay_ms()` 会让 CPU 在原地空转，这段时间里：
- 按键扫不到（你按了没反应）
- 屏幕不刷新
- 蜂鸣器不会按点响

计时器的所有"等待"都要换成**比时间戳**：

```c
// ✗ 阻塞：等 250ms 再响
Buzzer_ON();
Delay_ms(250);
Buzzer_OFF();

// ✓ 非阻塞：每轮看一眼，到点了才响
if (((Now - DoneTick) / BLINK_MS) % 2 == 0) Buzzer_ON();
else                                        Buzzer_OFF();
```

第二种写法看起来绕，但它是**唯一**能让"蜂鸣器在响的同时，按键还能响应"的写法。

## 九、排错表

| 现象 | 大概率原因 |
|---|---|
| 屏幕不亮 | `OLED_Init()` 没调；PB8/PB9 接反 |
| 数字一直是 0，按 KEY1 也不动 | TIM2 中断没进去 → 查通道名 `TIM2_IRQn`、函数名 `TIM2_IRQHandler`、有没有 `TIM_Cmd` |
| 数字在涨，但明显偏慢 | PSC/ARR 没减 1；或者在主循环里混进了 `Delay_ms()` |
| 数字在涨，一按 KEY1 就卡住 | Key.c 里还残留着 `while (引脚 == 0);` 的死等 |
| 按一下 KEY1，状态跳好几下 | 没做消抖，或者 `Event` 在主循环里被当成"持续状态"用了（它只报一次） |
| 长按切模式，切了十几次 | `Key_LongSent` 标记没写，每轮都上报 |
| 长按之后松手，又触发一次短按 | 松手时没检查 `Key_LongSent[i] == 0` |
| 秒表暂停 10 秒再开始，数字突然 +10 秒 | `LastTick = Now;` 写在了 `if (Running)` 里面，暂停时没更新 |
| 倒计时到 0 后数字还在往下减（显示成 99:xx） | 没写 `ElapsedMs = Preset;` 的钳位 |
| 到点蜂鸣器一直长鸣不停 | 蜂鸣器用 `Delay_ms` 控制通断，或者 `DoneTick` 没记 |
| 屏幕闪、刷新慢、按键迟钝 | 每轮都刷全屏。要按 `REFRESH_MS` 节流，且只刷变化的那几行 |

实在想不出来 → 对照 `_答案备份` 里的同名文件。
